一、云服务商选型

1.1 推荐方案：腾讯云

为什么选腾讯云？
  • VOD（视频点播）+ CSS（直播）SDK 最成熟，文档完善
  • VOD + COS + CDN 一体化，视频加载速度快
  • 企业认证后域名备案流程最顺（同主体下多个网站）
  • 教育类目资质审核相对宽松
  • 月付/年付灵活，前期成本低

2.3 部署流程（生产环境）

Step 1：购买服务器，初始化系统

购买2台 CVM → 重装 Ubuntu 22.04 → 设置 SSH 密钥登录 → 关闭密码登录

Step 2：安装基础软件

apt update && apt install nginx docker.io docker-compose certbot

Step 3：申请域名 + HTTPS 证书

域名注册 → 申请免费 SSL（Let's Encrypt）→ 配置 Nginx HTTPS

Step 4：配置负载均衡（CLB）

腾讯云控制台创建 CLB → 绑定2台后端 → 配置监听器（80/443）

Step 5：部署应用

git pull → docker-compose up -d → 健康检查

Step 6：配置 DNS 解析

域名解析指向 CLB 的公网 IP

三、数据库部署

3.1 推荐：云数据库（不开源自建）

⚠️ 不要在应用服务器上自建 MySQL！
自建数据库的痛点：主备复制要自己配、备份要自己写脚本、故障切换要手动、硬盘满了才发现没空间。
腾讯云 MySQL 高可用版：¥150-200/月，含主备自动切换 + 每日自动备份 + Binlog。

3.4 分库分表策略（Phase 3 后评估）

什么时候需要分库？
当单库数据量超过 500GB，或 MySQL QPS 持续超过 5000 时，考虑按业务拆分用户库/课程库/日志库。
Phase 1-2 数据量小（预估用户 < 10万），单库完全够用，不必过度设计。

四、域名与备案

⚠️ 这一步最花时间！提前2-3周开始走流程。
在中国大陆，所有面向用户访问的网站必须完成 ICP 备案，否则域名会被屏蔽。
如果使用腾讯云国内节点，备案可以直接在腾讯云控制台一站完成。

4.1 备案条件

  • 域名已完成实名认证（且实名信息和营业执照/身份证一致）
  • 有大陆服务器的云服务商（腾讯云/阿里云）
  • 企业为主体（需营业执照），或个人为主体（需身份证）
  • 网站内容符合教育类目要求（不能有视频裸聊/医疗问诊等敏感内容）

4.2 备案流程（腾讯云）

Step 1：注册域名 + 实名认证（1-3天）

在腾讯云/阿里云注册域名 → 填写实名信息 → 等待审核通过

Step 2：购买云服务器，获取备案码（1天）

需购买包月云服务器（≥3个月）才能申请备案码，费用 ¥30-50/月起

Step 3：提交备案申请（腾讯云系统，1天）

填写主体信息/网站信息 → 上传营业执照 + 法人身份证 + 网站真实性核验单

Step 4：初审（1-2天）

腾讯云客服初审材料 → 可能要求补充说明或修改内容

Step 5：短信核验（1天）

工信部短信链接 → 法人/网站负责人完成实名核验

Step 6：管局审核（7-20天，看省份）

各省通信管理局审核，广东/北京/上海较快（5-7天），其他省可能15-20天

Step 7：备案成功

获取备案号（穗ICP备xxxxxxx号）→ 挂在网站底部

4.3 备案时间线（2025年最新）

域名实名认证

约3天入库

材料准备

1-2天

服务商初审

1-2天（材料齐全当天）

短信核验

1天

管局审核

最长20个工作日（法规要求）

合计

最快5-7天
最长约25天

⚠️ 重要：根据工信部规定，省级通信管理局收到材料后，应在20个工作日内予以备案。实际速度因省份而异：广东/上海/北京较快（5-7天），其他省可能15-20天。

4.4 备案前后域名访问规则

阶段域名状态访问效果
未备案解析到国内 IP⚠️ 被运营商拦截，显示"该网站未完成备案"
备案中已购买服务器，解析未指向✅ 指向香港/海外 IP 可访问，国内 IP 不行
备案通过获得备案号✅ 正式上线，解析到国内 IP
💡 备案期间如何上线？
先用香港/海外服务器部署一个"维护页面"，告知用户"网站正在建设中"。
备案通过后，再把域名解析切到国内生产环境。

5.5 服务器文件备份

哪些文件需要备份？
  • /etc/nginx/ — Nginx 配置
  • /opt/app/ — 应用代码（已经在 Git 里，应该始终从 Git 拉取最新）
  • /root/.env — 环境变量（含密钥，必须存 Vault 或密码管理器）
  • /var/log/ — 日志目录（可选择性备份）
  • docker-compose.yml — 容器编排文件
# 推荐做法：用 Git 管理配置文件
git clone git@github.com:MungSmoothie/xkjt-config.git /opt/config
# 所有服务器的配置文件从 Git 统一拉取
# 密钥通过环境变量注入，不进 Git

六、安全加固

6.1 服务器安全

措施操作状态
SSH 密钥登录禁用密码登录，改用公私钥必做
SSH 端口改默认 22 端口为高位端口（如 2222）推荐
防火墙只开放 22/80/443，MySQL/Redis 仅允许内网必做
Fail2ban安装 fail2ban，自动封禁暴力破解 IP推荐
系统更新设置自动安全更新（unattended-upgrades）必做
最小化安装不装不必要的软件，只保留必要服务必做

6.2 数据库安全

措施操作
强密码MySQL/Redis 密码 ≥ 32 位随机字符串，存腾讯云 Secrets Manager
最小权限应用连接用只读账号，运营后台用读写账号，分离
内网访问MySQL/Redis 禁止公网访问，仅 VPC 内网连接
SSL 连接数据库连接全部走 SSL
敏感字段加密密码字段用 bcrypt/bcryptjs，不可逆加密
审计日志开启 MySQL 审计日志，记录所有 DDL 操作

6.3 HTTPS 配置（2025年更新）

  • 使用 Let's Encrypt 免费证书，Nginx 现已原生支持 ACME 协议，可直接自动申请和续期，无需额外工具
  • 使用 certbot 或 acme.sh 管理证书（传统方式，仍然推荐）
  • 强制跳转到 HTTPS（Nginx 301 重定向）
  • HTTP Strict Transport Security（HSTS）头部开启
💡 推荐：Nginx 1.18+ 内置 ACME 支持，可配置自动续期，实现真正的"设置后不管"。参考工具：acme.sh + cron 定时任务。

7.3 日志管理

  • 应用日志：结构化 JSON 格式，输出到 stdout，docker-compose 收集到文件
  • nginx 日志：access.log + error.log，每日轮转
  • 日志保留：7天热数据 + 30天冷数据（COS 归档）
  • 工具：ELK 或腾讯云日志服务（CLS），按量计费 ¥0.35/GB
